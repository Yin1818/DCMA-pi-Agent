# Agent 查询证据图表设计

日期：2026-10-22
状态：用户已确认并实施。定向测试和真实模拟数据链路通过；浏览器CSV下载受组织策略限制，详见绘图验收记录。

## 1. 已确认的目标

用户选择 ECharts，采用一个统一绘图工具。Agent 根据问题选择图型和指标，程序使用真实查询证据生成图表，聊天区域以清晰、美观、可交互的图表卡片展示。

首批包括折线图、散点图、柱状图、直方图；卡片提供来源、时间范围、单位状态、数量、聚合说明，以及放大、数据视图、PNG/SVG 下载和 CSV 导出。历史会话恢复当时的图表快照，重新查询由用户主动触发。

本次只增加聊天绘图能力，现有展板、设备选择和 MySQL 只读约束不变。不引入模型执行 Python、JavaScript、HTML 或任意 ECharts 配置的能力。

## 2. 实施前代码与需要解决的问题

- `tools/index.ts` 注册 16 项工具。分析工具从 `windowFor` 获取同轮缓存的完整窗口，模型通常只收到统计结果。
- `tools/runtime-files.ts` 的 `evidenceId` 只在当前请求中有效。它不能直接作为历史图表的永久数据地址。
- `src/api.ts` 当前只接收文字增量、错误及完成事件；`ChatMessage` 没有图表字段。
- `src/storage.ts` 会逐字段恢复消息，需要显式保留图表引用。
- `MessageContent.tsx` 仅渲染 Markdown，现有 SVG 图表只用于右侧监测卡片和展板。

例如，模型已经查询了三分钟电流与温度统计，再要散点图时，不能把两项均值拼成点，也不应重新查询一份可能已改变的数据。绘图必须取得原查询窗口中的逐行配对记录，并保存为独立快照。

## 3. 总体链路

1. Agent 调用现有查询或统计工具。
2. 后端为成功证据保存本轮内部绘图数据引用；原始数据不需要再次经过模型输出。
3. Agent 调用 `create_analysis_chart`，提供证据编号、图型、字段和受约束的聚合选项。
4. 后端验证证据归属、字段、数据范围和图型，将数据转换成统一 `ChartArtifact` 并持久化。
5. 工具只向模型返回图表摘要及图表编号；服务端另发 `chart` 结构化消息事件。
6. 前端把图表引用关联到当前助手消息，获取快照并使用本地生成的 ECharts 配置渲染。
7. 历史会话按保存的图表编号读取原快照，不自动重新读取 MySQL 或调用模型。

## 4. 统一绘图工具

名称：`create_analysis_chart`。新增后共 17 项工具；仍沿用每轮 16 次调用、8 次数据库读取、4 个分析窗口等现有预算。每轮最多生成 3 张图。

| 参数 | 约束与含义 |
| --- | --- |
| `evidenceId` | 必填，本轮成功、可绘图的证据编号；不能使用历史文本中的编号 |
| `kind` | 必填，`line`、`scatter`、`bar`、`histogram` |
| `title` | 可选，最多 100 字符的纯文本；省略由字段标签和图型生成 |
| `metrics` | 折线、柱状必填，1 至 4 个不重复的白名单数值字段；直方图恰好一个；散点图的纵轴恰好一个 |
| `xMetric` | 散点图必填，另一个白名单数值字段；其他图型不接受 |
| `bucketSeconds` | 时间聚合时可选，有限正数，最多 200 个桶；直方图、散点图不接受 |
| `aggregation` | 时间柱状图必填，`mean`、`min`、`max`；折线省略表示原始序列，提供聚合时明确标注；不提供任意表达式 |
| `bins` | 直方图可选，整数 5 至 50，默认 20；其他图型不接受 |

代码事件证据可生成“故障/报警代码—事件次数”柱状图，使用服务器计算结果，不把非零点数当事件次数。窗口比较证据可生成 A/B 指标均值柱状图，保留各窗口范围。二者不接受时间分桶参数。

首版支持来源：当前采样预览、完整窗口质量/统计/超限/状态/综合证据、窗口比较及代码事件统计。目录、设备资料、知识、告警列表、报告与图表本身不能作为数值绘图来源。任意字段原始查询首版不直接接入绘图；需要图表时改用完整窗口或当前采样工具，避免把分页预览误当完整数据。

工具描述说明适用图型、前置证据、参数组合和禁止情况。不因用户要一张图而查齐全部分析工具；无有效数据时明确失败，不补零或生成示例数据。

## 5. 查询证据与绘图数据关联

在工具执行层保留服务器内部的证据数据映射，区分：

- 完整窗口：引用同轮 `AnalysisWindow`，不重复查询；只允许证据实际覆盖、参与分析的字段。
- 当前采样：只引用工具实际返回的预览范围，保留 `hasMore`、`truncated` 等标记，不能升级为完整窗口。
- 代码事件/窗口对比：引用程序计算出的类别和计数/均值，不把模型叙述作为数据。

映射在工具成功且证据登记后才建立；失败和超预算结果没有绘图资格。映射随本轮结束释放。散点图必须来自同一来源、同一行的两个有效数值；两个窗口不能按数组下标配对。缺失配对记录排除并计数。

## 6. 图型与数据规则

### 折线图

- 横轴按真实采集时间定位，显示北京时间并标注暂定解释。
- 缺失值断线，不插值、不补零；有可靠间断规则时按规则断开，否则不编造采样周期。
- 原始序列与分桶均值明确区分。单点、恒定值、负值正常显示。
- 多指标单位不同或尚未确认时分成独立纵轴面板，共用时间轴，避免直接混在同一数值轴上。
- 阈值线仅取已引用超限证据中的规则；图中标明依据与单位。不允许模型直接填写未经核实的新阈值。

### 散点图

- 按同一条原始记录配对，明确横纵轴及单位状态。
- 支持悬停查看两项数值和采集时间。
- 图中不自动生成因果结论、回归线或相关系数；后续如需这些功能，应先增加明确的程序计算和验收。

### 柱状图

- 支持时间分桶指标、A/B 窗口均值、代码事件次数三类数据。
- 时间分桶说明统计方法；空桶保持缺失；类别计数纵轴从零开始。
- 正负值保留，未知计数不能转换为零。

### 直方图

- 使用完整证据窗口的有效数值计算所有箱计数，不用绘图降采样后的点计算分布。
- 显示箱边界、频数和有效样本数；最后一个箱包含最大值。
- 恒定值生成合理的显示跨度，但不改变原始值或频数。

## 7. 数据量与快照

沿用来源窗口最多 7 天、20000 行的限制。模型不接收完整图表数据；工具结果只返回摘要。图表快照只保存选定字段、时间/必要行标识、聚合数据与来源元信息，不复制无关原始列。

- 每图最多 4 个指标、200 个聚合桶。
- 折线显示最多约 2000 点/指标；需要减少点数时使用保持极值及缺失边界的确定性算法。无法在上限内保留必要断点时要求缩小范围，不跨缺失区间连线。
- 散点最多显示 5000 对点，超限做确定性抽样，明确总有效对数和实际显示数量。
- CSV 导出完整快照数据，而非用户当前缩放可见部分。聚合图导出聚合值，按钮标为“导出图表数据”，不称原始数据。
- 每份快照 JSON 最多 4 MiB，本机最多 100 份；达到上限明确提示人工归档，不静默删除历史图表。

持久化位置：`packages/web/.dcma-runtime/charts/`。目录 `0700`，文件 `0600`，UUID 文件名，原子写入，拒绝路径穿越和符号链接。既有 Git 忽略规则覆盖该目录。敏感数据不会写入公开设计和说明文档。

## 8. 结构化结果和接口

`ChartArtifact` 包含：

- `version: 1`、`id`、`createdAt`、`kind`、纯文本标题。
- 来源表、来源种类、原查询工具和证据编号、查询时间、查询范围、实际覆盖范围。
- 设备身份（仅原查询已取得时）、字段标签、可空单位及单位来源状态。
- 受约束的坐标轴/系列、数据表、聚合设置、缺失与抽样说明。
- 来自超限证据的可选阈值标记。

不保存任意 ECharts option、HTML、JavaScript、回调函数或外部数据 URL。

接口：

- `GET /api/tools/charts/{uuid}.json`：读取固定快照，带 `no-store` 与 `nosniff`。
- `GET /api/tools/charts/{uuid}.csv`：下载该快照的图表数据，正确转义 CSV 并防止文本公式注入。
- 继承本机 Host/Origin 限制；不支持上传任意快照或通过 GET 改动数据。

PNG、SVG 由前端当前图表导出。完整下载包含标题、来源、范围、单位与聚合/抽样说明；缩放后导出需标明可见范围。

新增流事件：`{type: "chart", chart: {id, version: 1}}`，仅在工具成功且快照保存成功后由服务端发出。前端验证编号并去重；模型文字中伪造的 JSON 不会触发图表渲染。

## 9. 聊天展示与历史恢复

新增 `AnalysisChartCard`，由 `ChatView` 放在对应助手消息文字下方。保留现有聊天、右侧监测栏和展板布局。

- 白色卡片、细边框、适量留白，蓝色为主，其他系列使用可区分配色和线型。
- 标题区展示图名、设备及模拟/历史采集标记；副标题显示范围和数据取得时间。
- 主图高度约 300px，移动端轴标签减少，不挤压成不可读小字。
- 悬停读数、图例、时间范围缩放；数据视图可横向滚动并分页，避免一次渲染 20000 行。
- 操作区提供放大、PNG、SVG、CSV及“重新查询该时段”。后者向对话发送服务器范围生成的明确请求，产生新消息和新快照，不修改原历史快照，也不自动扩大为当前时间。
- 页脚说明有效/缺失数量、显示点数、时间和单位假设、完整/预览及聚合方式。
- 加载、无数据、文件缺失、格式不支持及服务不可用有独立状态，不显示假曲线。
- 图表提供文字摘要和可访问数据表；不能只靠颜色区分故障、系列或状态。

`ChatMessage` 增加可选 `charts` 引用数组；浏览器只存引用，完整数值保留在本机快照。`loadWorkspace` 校验并恢复引用；已有无图表消息保持正常。会话 JSON 导出包含引用，但跨电脑迁移需要额外复制本机快照，首版不宣称导出会话即可迁移全部图表数据。

ECharts 采用精确版本依赖、按需导入和组件卸载清理；窗口或全屏大小变化后 resize，聊天列表按需初始化可见图表，避免历史图表全部同时创建。具体版本在实施时查询官方发布及兼容条件后固定。安装使用 `npm install --ignore-scripts`，依赖和锁文件变化纳入检查。

## 10. 验收标准

1. 四种图型用已知合成数据验证坐标、配对、分桶、频数、缺失和零值；无效字段、错误参数组合、旧证据编号和不可绘图证据被拒绝。
2. 图表使用原查询快照；绘图不会额外读取 MySQL；改变数据库后旧图表不变。
3. HTTP 校验 UUID、只读方法、大小、文件权限、符号链接和 CSV 转义；损坏快照不能进入渲染。
4. 验证 NDJSON 图表事件、错误与取消、去重、localStorage 恢复、后端重启及历史会话重开。
5. 桌面和窄屏下实际查看卡片、悬停、缩放、放大、数据视图及下载图片，检查中文、轴标签与说明不重叠。
6. 使用真实 Agent 自然语言分别请求四种图型，检查调用及图表数值与原证据一致；查询失败不生成示例图；不要求绘图的纯文字问题不强行生成图。
7. 按项目要求执行 `npm run check` 和相关定向回归。真实模型验收不混入默认离线测试，不运行整个根 Vitest 套件。
