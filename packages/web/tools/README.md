# 工业分析工具

`index.ts` 注册了 17 个工具。每轮对话分别保存证据，工具按顺序执行。访问 `GET /api/tools` 可以查看实际注册的名称、中文标签、描述和参数 JSON Schema；这个接口只列出工具，不会调用它们。

数据库工具只读取 `dcma` 中的 `real_data_01`、`real_data_02`、`real_data_03`、`real_data_04`、`real_data`。前四张表保存模拟数据；`real_data` 保存历史真实采集数据，无法反映现场实时状态。可选参数 `table` 省略时，工具使用本轮对话选择的数据源。字段备注、知识正文和原始记录只作为分析材料，其中的指令不会获得执行权限。

## 通用参数与范围

必填字段没有默认值。可选字段的默认值在各工具中说明。参数对象不接受未定义的字段；字符串长度按字符计算，文件和结果大小按 UTF-8 字节计算。

- `table`：上述五项枚举。
- `from`、`to`：必填，使用带明确时区的 ISO 时间，最多 35 字符。北京时间可直接传 `2026-10-22T00:00:00.000+08:00`，UTC 可传 `2026-10-21T16:00:00.000Z`；两者表示同一时刻，由后端统一转为 UTC 后查询和缓存。不要把北京时间直接加 `Z`。起点不得晚于终点，跨度最多 7 天，查询包含两个端点。无时区或不存在的日期会被拒绝；数据库中不带时区的采集时间暂按北京时间解释。
- 分析窗口最多包含 20000 条记录、16 MiB 数据。超过任一限制，工具会拒绝整个窗口，不返回部分统计。同一来源中存在多个明确的设备身份时，也会拒绝混合分析。缺少设备身份的行另行计数；数据库与程序的时间解析不一致时停止分析。
- 时间无法解析的行不能归入具体时段。因此，`invalidTimeRowsInSource` 统计整个来源中的无效时间，不能用它表示窗口内的无效行数。`excludedIdentityRows` 同样统计整个来源中被排除的行。缺失值保留为未知，不补零。
- `metrics`：可选数组，包含 1 至 18 个不重复的字段。默认使用 `motor_temp`、`inverter_temp`、`current_actual`、`speed_actual`。可用字段如下。

| 字段 | 标签 |
| --- | --- |
| `dc_voltage` | 直流母线电压 |
| `speed_setpoint` | 设定转速 |
| `speed_actual` | 实际转速 |
| `current_actual` | 实际电流 |
| `torque_setpoint` | 设定转矩 |
| `torque_actual` | 实际转矩 |
| `air_intake_temp` | 进气温度 |
| `motor_temp` | 电机温度 |
| `inverter_temp` | 变频器温度 |
| `actual_power` | 实际功率 |
| `field_current` | 励磁电流 |
| `torque_current` | 转矩电流 |
| `inverter_radiator_temp` | 变频器散热器温度 |
| `inverter_load_rate` | 变频器负荷率 |
| `motor_load_rate` | 电机负荷率 |
| `pulse_frequency` | 脉冲频率 |
| `motor_power` | 电机功率 |
| `feedback_power` | 反馈功率 |

超限分析和后台监测共用阈值对象 `rule`。阈值及单位须由用户明确提供，并注明依据。示例中的数值只用于说明调用格式，不是设备推荐值。

| 字段 | 必填、类型与限制 |
| --- | --- |
| `metric` | 必填，上表字段枚举之一 |
| `operator` | 必填，`gt`（大于）或 `lt`（小于） |
| `threshold` | 必填，有限数值，触发阈值 |
| `recoveryThreshold` | 可选，有限数值，默认等于 `threshold`；`gt` 时不得高于触发阈值，`lt` 时不得低于触发阈值 |
| `minDurationSeconds` | 必填，有限数值，0 至 604800 秒，最短已观察持续跨度 |
| `maxGapSeconds` | 必填，有限数值，`0 < 值 <= 86400`，允许的最大相邻采样间隔 |
| `unit` | 必填，非空字符串，最多 32 字符 |
| `source` | 必填，非空字符串，最多 300 字符，阈值依据 |

## 执行预算与证据

每轮最多调用工具 16 次、读取数据库 8 次，并分析 4 个不同窗口。相同 `table/from/to` 的请求复用本轮首次取得的完整窗口。比较两个时段通常占用两个窗口；查询目录、原始记录和当前采样也会消耗数据库读取额度。

每轮工具上下文的有效时间为 90 秒，单次查询最多等待 30 秒，且不能超过本轮剩余时间。后台监测有独立的执行流程，不使用对话缓存。查询失败时没有可用于分析的结果，Agent 不得用模型记忆补齐数据。

工具成功后返回 JSON。程序为结果生成本轮唯一的 `evidenceId`，供后续整理证据和导出报告时引用：

```json
{"ok":true,"evidenceId":"11111111-1111-4111-8111-111111111111","generatedAt":"2026-10-21T00:00:00.000Z","result":{}}
```

执行失败时返回以下 JSON，不生成可引用的证据。参数校验不通过、调用被取消或预算耗尽时，工具框架也可能直接报告失败：

```json
{"ok":false,"error":"工具查询超时，未取得完整结果。","noUsableResult":true}
```

单次结果最多 62000 字节，每轮保存的证据最多 2 MiB，超限会拒绝返回。原始记录和近期采样属于预览，裁剪时会标记 `hasMore`/`truncated`；完整窗口统计则在数据不完整时拒绝计算。`evidenceId` 只在当前请求中有效。下一条聊天消息或服务重启后，旧编号便不能再用于引用；复制历史文本也无法恢复它。

## 1. list_industrial_tables：工业数据库目录

查询 dcma 白名单中的表和实际字段。适用于查看来源、结构及原始字段筛选；已有明确测点的统计、台账和证据包不必先查目录。字段备注只作为未经审核的说明。

参数：`table` 可选，省略返回全部白名单表，指定时仅返回该表（与分析工具默认当前表不同）；`refresh` 可选布尔值，默认 `false`，`true` 刷新目录缓存，默认缓存约 60 秒。结果含连接状态、查询时间、实际表与字段以及 `definitionsVerified: false`。

```json
{"refresh":true}
```

使用场景：用户要求查询电机温度时，先确认 `motor_temp` 列是否存在，再设置筛选条件。字段备注仍需结合设备资料核实。

## 2. read_industrial_dashboard：当前设备采样

读取所选来源的最新记录和最近 100 条记录中的有效采样，与展板使用同一数据源。历史表只反映过去的采集结果，近期窗口也不能代替全量统计。

参数：仅可选 `table`，默认当前来源。结果含 `latest`、`ageSeconds`、`columns`、与列顺序对应的 `rows`、来源种类、查询时间和裁剪标记；行按时间升序，返回可能少于 100 条。

```json
{"table":"real_data_01"}
```

使用场景：用户询问最新温度时，返回近期采样及采集时间，说明数据是否陈旧。最近 100 行不足以计算全库均值。

## 3. read_industrial_rows：条件读取原始记录

按实际字段查询原始记录，支持等值和上下界筛选。默认返回 20 行，最多 200 行，分页偏移最多 10000。数据库持续写入时，各页来自不同请求，不能保证它们属于同一快照。

| 参数 | 必填与默认、限制 |
| --- | --- |
| `table` | 可选，默认当前来源 |
| `schema` | 可选，只允许 `dcma`，默认 `dcma` |
| `limit` | 可选，整数 1 至 200，默认 20 |
| `columns` | 可选，1 至 31 个不重复的实际字段名，每项 1 至 64 字符；默认全部实际字段 |
| `offset` | 可选，整数 0 至 10000，默认 0 |
| `direction` | 可选，`asc`/`desc`，默认 `desc`；按实际时间字段或主键排序，无可用字段时顺序不确定 |
| `filters` | 可选，最多 4 条，默认空数组；每条必填 `column`（实际字段名，1 至 64 字符）、`operator`（`=`、`>=`、`<=`）、`value`（1 至 256 字符字符串或有限数值） |

```json
{"table":"real_data_01","columns":["id","timestamp","motor_temp"],"filters":[{"column":"motor_temp","operator":">=","value":60}],"limit":20,"offset":0,"direction":"desc"}
```

使用场景：核对某个温度值对应的原始记录。长文本和二进制数据可能被截断，原始查询最多返回约 64KB，工具返回时还受 62000 字节的限制。超限时可减少列数或行数。

## 4. get_device_profile：设备与测点资料

读取人工填写的设备型号、版本、测点单位和状态规则。资料缺失时返回未知，不从表名推断型号或额定值。

参数：仅可选 `table`，默认当前来源。结果含 `configured`、`configurationPresent`、可空身份及来源、设备台账名、位置、投运日期、额定值及依据、全部字段标签、全部数值测点的单位及单位来源状态、`stateRules`。未提供的资料返回 `null`，不会从表名或读数推断。已配置单位只标记 `user_configured`，来源为 `user_provided`，`verified` 始终为 `false`。额定值不自动当作报警阈值。

```json
{"table":"real_data_01"}
```

使用场景：分析转速前检查 `speed_actual` 的单位。若返回 `unit: null`，Agent 应请用户确认，不能自行填为 rpm。

## 5. check_data_quality：数据质量检查

检查整个受限窗口内的缺失值、重复时间、零值和采样间断。零值单独计数，不直接判为故障；无法归入具体时段的无效时间另行报告。

参数：必填 `from`、`to`、`maxGapSeconds`（有限数值，`0 < 值 <= 86400`）；可选 `table`、`metrics`，默认遵循通用参数。结果按字段统计有效、缺失、零值、缺失比例及实际字段是否存在，报告重复时间和重复行、间断数量及最多 20 个间断示例；`gapsTruncated` 表示示例截断。窗口两端未覆盖的跨度另以 `leadingGapSeconds`、`trailingGapSeconds` 返回，不直接认定采集失败。

```json
{"table":"real_data_01","from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z","metrics":["motor_temp"],"maxGapSeconds":60}
```

使用场景：解释温度均值变化前，先检查该时段是否存在大量缺失或长时间采样中断。零值数量只说明数据分布，不能换算成故障次数。

## 6. summarize_metrics：时间窗口统计

由程序计算整个受限窗口的采样均值、总体标准差、极值和首末变化率，也可按指定秒数分组。均值按采样点计算，不按时间加权，结果仅覆盖所选窗口。

参数：必填 `from`、`to`；可选 `table`、`metrics`；可选 `bucketSeconds` 为有限数值，`0 < 值 <= 604800`，默认不分桶，最多 200 桶。桶边界左闭右开，最后一桶包含整个窗口终点。

```json
{"from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z","metrics":["motor_temp","current_actual"],"bucketSeconds":600}
```

使用场景：查看每 10 分钟的温度均值。`populationStdDev` 表示总体标准差，`slopePerSecond` 取首末唯一时间戳上的有效值之差，再除以时间差；重复时间戳不参与首末值选择。缺失或溢出的统计返回 `null`，应解释为无法计算。

## 7. compare_metric_windows：窗口对比

比较同一来源的两个时间段，返回均值差和变化率。单位或工况未确认时，结果只能说明观测到的差异，不能解释其原因。

参数：必填 `a`、`b`，两者均仅含必填 `from`、`to`，分别遵循 7 天窗口约束；可选 `table`、`metrics`。差值为 B 均值减 A 均值，变化百分比为差值除以 A 均值绝对值；A 为零或缺失时百分比为 `null`。

```json
{"table":"real_data_01","a":{"from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z"},"b":{"from":"2026-10-20T01:00:00.001Z","to":"2026-10-20T02:00:00.000Z"},"metrics":["motor_temp"]}
```

使用场景：对比故障前后两段采样的温度均值。即使观察到升高，结果仍保留 `causalInterpretation: "not_established"`，不会直接归因于设备损坏。

## 8. analyze_threshold_events：连续超限分析

使用用户明确给定的阈值和单位计算连续超限事件，支持回差和已观察持续时间。缺失值、重复时间或长采样间断会打断事件；仪表量程不能自动充当阈值。

参数：必填 `from`、`to`、完整 `rule`；可选 `table`。`rule` 的全部字段与恢复方向约束见共同阈值表。返回完整窗口汇总及最近最多 50 个事件，`eventsTruncated` 表示明细截断。持续时间为 `lastSeenAt - startedAt`，不包含恢复采样时刻；只计已观察采样跨度。

```json
{"from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z","rule":{"metric":"motor_temp","operator":"gt","threshold":80,"recoveryThreshold":75,"minDurationSeconds":30,"maxGapSeconds":10,"unit":"用户确认单位","source":"调用格式示例，实际使用前替换为已确认依据"}}
```

使用场景：按用户给定的阈值查找持续超限。工具不会把单个高值或被重复时间、缺失值、长间断隔开的采样拼成连续 30 秒超限。如果窗口开始时已经超限，会标明起点不确定。

## 9. get_code_events：故障与报警事件

按展板的代码事件算法分析所选窗口，将连续出现的同一代码合并为事件。窗口开始时已异常的事件会标注起点不确定；未观察到结束，也不能说明设备当前仍有故障。工具不提供厂家代码释义。

参数：必填 `from`、`to`；可选 `table`、`page`（整数 1 至 200，默认 1）。每页最多 50 个事件，代码汇总最多 100 项，代码文本最多 128 字符；使用各自截断标记及 `hasMore`。仅分析传入窗口，没有读取窗口外前驱或后继记录。

```json
{"table":"real_data_01","from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z","page":1}
```

案例：统计这一小时内观测到的报警事件。缺少故障码或报警码列时拒绝分析；字段存在但无有效代码观测时，对应次数返回 `null`，并提供 `codeCoverage`、`status: "unknown"` 或 `partial`，不能将其解释为0次。代码变化或归零结束事件；缺失采样作标记，不按长间断自动拆分。与阈值连续性规则不同。展板全来源故障历史会读取来源历史后筛选事件，本工具只拥有窗口内记录，起止和计数可能不同；不能将 `scope: "window_only"` 称为全来源历史。

## 10. assess_device_state：设备状态评估

检查采样是否新鲜，并按人工配置的规则评估设备状态。型号或状态规则缺失时保留未知；历史或过期数据不能证明设备当前正常。

参数：必填 `from`、`to`、`staleAfterSeconds`（有限数值，1 至 86400）；可选 `table`。状态规则从该表本地配置读取，不由模型临时生成。返回采样年龄、`freshness`、规则命中的 `observedState`、受新鲜度及历史范围约束的 `currentState`、条件证据和规则来源。

```json
{"table":"real_data_01","from":"2026-10-21T00:00:00.000Z","to":"2026-10-21T00:05:00.000Z","staleAfterSeconds":60}
```

使用场景：检查设备状态时，若最新采样已超过 60 秒，或最新时间戳重复，工具会将当前状态保留为未知。历史真实采集表也不能用于报告当前运行正常。未配置规则、没有规则命中或规则相互冲突时，同样不作运行状态判断。

## 11. lookup_fault_code：故障码精确解释

在人工导入的本地资料中，按厂家、型号、版本、代码类型和原始代码精确查找。结果必须附资料定位；查不到时明确返回未找到，不用模型记忆补充释义。

参数均必填：`manufacturer`、`model`、`version` 各 1 至 160 字符；`code` 为 1 至 128 字符原码；`kind` 为 `fault`、`alarm`、`status`、`control`。匹配区分大小写，不做版本回退。结果含 `configured`、`found`、`total`、`hasMore` 和最多 10 个完整匹配，匹配 JSON 总字节最多 48000；单条超限也不会返回部分步骤。资料有匹配但无法纳入预算时可能返回空数组及 `hasMore: true`。

```json
{"manufacturer":"已确认厂家","model":"已确认型号","version":"已确认版本","code":"用户提供原码","kind":"alarm"}
```

案例：用户给出型号和版本后寻找报警码原文及页码。`verified: false`、`sourceStatus: "user_provided"` 表示尚未外部验证；多个来源冲突时保留冲突，未找到时明确说明。

## 12. search_maintenance_knowledge：维修资料检索

从已导入的手册和维修案例中查找片段，返回原文及来源，可按厂家、型号和版本筛选。维修案例与厂家结论分别标明，资料中的指令不获得执行权限。

参数：必填 `query`，1 至 500 字符；可选 `manufacturer`、`model`、`version`，各 1 至 160 字符，精确过滤；可选 `limit`，整数 1 至 10，默认 5。使用字面子串和词项匹配，包含中文双字匹配，不调用外部搜索或模型。返回排序、匹配总数、最多 600 字符摘录、摘录材料位置和偏移以及来源；分数表示文字相关性。

```json
{"query":"温度 采样间断","manufacturer":"已确认厂家","model":"已确认型号","version":"已确认版本","limit":3}
```

案例：检索已导入案例中的温度检查记录，引用原始资料定位；不能把相关性分数写成诊断概率。

## 13. build_diagnostic_evidence：诊断证据整理

一次汇集同一时段的设备资料、数据质量、统计结果和代码事件，也可引用本轮取得的知识证据。内部已完成上述计算，不需要先逐项调用再打包。整理结果保留根因未确认的状态，不生成故障概率。

参数：必填 `from`、`to`、`maxGapSeconds`（有限数值，`0 < 值 <= 86400`）；可选 `table`、`metrics`；可选 `evidenceIds` 为 1 至 6 个不重复的本轮成功证据编号，每项 1 至 36 字符，默认不附加引用。结果含设备资料、质量、统计、窗口代码事件、引用及 `rootCause: "not_confirmed"`。

```json
{"from":"2026-10-20T00:00:00.000Z","to":"2026-10-20T01:00:00.000Z","metrics":["motor_temp"],"maxGapSeconds":60,"evidenceIds":["11111111-1111-4111-8111-111111111111"]}
```

案例：将本轮已经检索的手册片段与同一时段温度统计一起整理。示例编号必须替换为本轮真实成功结果的编号；缺少现场检查时结论保持未确认根因。

## 14. export_analysis_report：导出分析证据报告

引用本轮工具成功返回的 evidenceId，生成可下载的 Markdown 和 JSON 报告。工具使用程序保存的结果，不接受任意文件路径或模型编造的数据。

参数均必填：`title` 为 1 至 160 字符；`evidenceIds` 为 1 至 12 个不重复的本轮成功证据编号，每项 1 至 36 字符。报告保留工具、参数、时间、结果，不接受独立编造的数据。JSON 报告最多 1 MiB；本地最多保存约 100 对报告文件，达到上限后须人工归档，不自动删除。

```json
{"title":"一小时温度分析证据","evidenceIds":["11111111-1111-4111-8111-111111111111"]}
```

案例：统计工具成功后，立即用其真实编号导出。返回 `markdownUrl`、`jsonUrl`；下载端点为 `GET /api/tools/reports/{reportId}.md` 和 `.json`。不能引用上轮聊天中的编号；已生成的本地报告在服务重启后仍可按 ID 下载，除非人工移除。读取端点拒绝任意路径和文件名。

## 15. get_alert_history：后台告警记录

读取保存在本机的规则告警、恢复记录和数据未知事件。没有监测任务时，空记录不能说明设备正常。告警保存在本地，不发送外部通知。

参数全部可选：`taskId` 为现存任务 UUID（Schema 字符串 1 至 36，执行时校验 UUID）；`state` 为 `active`、`recovered`、`unknown`、`all`，默认不过滤；`limit` 为整数 5 至 100，默认 50。按最近记录优先，返回 `total`、`droppedAlerts`、`serviceError`。

```json
{"state":"unknown","limit":20}
```

案例：查看数据库中断期间产生的数据未知事件。未知不会自动把未恢复告警标成恢复；`recovered` 且 `closedReason: "rule_changed"` 表示规则被修改，不能解释为设备已恢复。

## 16. manage_monitoring_task：后台监测任务管理

list 用于查询任务。create、update、pause 和 resume 会生成待确认操作，Agent 需展示 approvalPath，由用户点击确认后才生效。工具不控制设备，也不发送外部通知。

| 参数 | 必填与默认、限制 |
| --- | --- |
| `action` | 必填，`list`、`create`、`update`、`pause`、`resume` |
| `taskId` | `update`/`pause`/`resume` 必填现存任务 UUID；`create`/`list` 不需要；Schema 限 1 至 36 字符 |
| `spec` | `create`/`update` 必填完整对象；其他动作不需要 |
| `spec.table` | 必填五表枚举，没有当前来源默认 |
| `spec.intervalSeconds` | 必填整数，30 至 86400，并且不得大于 `windowSeconds` |
| `spec.windowSeconds` | 必填整数，60 至 3600，滚动查询窗口 |
| `spec.staleAfterSeconds` | 必填整数，30 至 86400，新鲜度上限 |
| `spec.rule` | 必填共同阈值对象；另要求 `minDurationSeconds <= windowSeconds` 且 `maxGapSeconds <= windowSeconds`；`unit`/`source` 不含控制字符，来源不接受 URL 或敏感凭据文本 |

```json
{"action":"create","spec":{"table":"real_data_01","intervalSeconds":60,"windowSeconds":300,"staleAfterSeconds":120,"rule":{"metric":"motor_temp","operator":"gt","threshold":80,"recoveryThreshold":75,"minDurationSeconds":30,"maxGapSeconds":60,"unit":"用户确认单位","source":"调用格式示例，实际使用前替换为已确认依据"}}}
```

案例：用户明确给定阈值后生成提案，显示返回的 `approvalPath`（`/api/monitoring/confirm/{proposalId}`），由用户打开本机页面核对设备、规则和周期并点击按钮。工具调用本身不会启用任务；提案状态为 `pending_confirmation`，10 分钟后失效，每次只能确认一次，重启服务会清除未确认提案。

确认后的任务和告警写入 `monitoring.json`。最多保存 20 个任务、1000 条告警，超出容量后丢弃的告警数量可以查询。

关闭浏览器后，只要本机后端仍在运行，活动任务就会继续。退出后端会停止执行；重启后，此前确认的活动任务恢复运行，暂停任务保持暂停。服务不会补跑停机期间的数据，执行时间也不保证严格准点。存储出错时会停止监测并报告服务错误，此时不能判断设备是否健康。

后台每次只读当前滚动窗口，并检查最新有效采样年龄；无有效采样、过期、未来时间、历史真实来源、读取失败或已配置单位与规则单位冲突时记为未知。任务只维护本机告警和恢复证据，不发送邮件、短信、Webhook 或其他外部通知。

## 配置与验证范围

服务端使用 `packages/web/.dcma-runtime/` 私有目录，目录权限 `0700`、程序生成报告和存储文件权限 `0600`。设备资料为 `profiles.json`，知识资料为 `knowledge.json`；配置格式、各字段限制、来源声明及状态规则见 [配置说明](config/README.md)。每次知识查询重新读取配置文件；配置损坏不使用默认资料替代。仓库只包含 `.example.json` 格式占位符，没有可直接启用的真实厂家代码解释、额定值、状态含义或维修知识。

真实模型与校园 MySQL 的验收记录见 [2026-10-22 验收记录](验收记录_2026-10-22.md)。该验收检查工具选择、参数、执行和下载，不代表现场故障诊断效果已经验证。真实厂家资料与状态规则尚需人工补充。


## 17. create_analysis_chart：查询证据绘图

从本轮已经成功取得的查询证据生成图表。模型选择图型和指标，程序使用保存的窗口或统计结果计算数据；模型不能填写点值、SQL、ECharts 配置或文件路径。工具本身不再次查询 MySQL。

| 参数 | 必填、类型与限制 |
| --- | --- |
| `evidenceId` | 必填，本轮成功查询的证据编号；旧轮、知识或报告证据不可绘图 |
| `kind` | 必填，`line`、`scatter`、`bar`、`histogram` |
| `title` | 可选，1至100字符单行标题；默认由指标和图型生成 |
| `metrics` | 窗口绘图必填，1至4个不重复数值字段，必须包含在证据中；散点与直方图仅一个纵轴/统计指标。A/B比较可省略，默认取实际比较指标前4项；代码事件图省略 |
| `xMetric` | 仅散点必填，证据中的另一个数值指标；与纵轴同一行配对 |
| `bucketSeconds` | 时间柱状图必填，折线可选，正有限秒数且不超过604800；最多200桶 |
| `aggregation` | 时间分桶时与 `bucketSeconds` 同时指定，`mean`、`min`、`max` |
| `bins` | 仅直方图使用，整数5至50，默认20 |

例：先调用 `summarize_metrics` 查询明确时段的 `motor_temp` 和 `current_actual`，再将成功结果中的编号代入：

```json
{"evidenceId":"11111111-1111-4111-8111-111111111111","kind":"scatter","xMetric":"current_actual","metrics":["motor_temp"],"title":"电流与电机温度的配对分布"}
```

场景：用户询问电流升高时温度是否也升高。程序只保留同一记录中两字段都有效的配对，提示排除数量；图形只能说明关联分布，不能证明因果或故障。

支持来源：当前设备近期预览、数据质量、统计、超限、状态与诊断窗口，以及窗口比较和代码事件的程序计算结果。原始条件记录查询不作为绘图证据。A/B柱状图使用窗口均值；代码柱状图使用连续事件次数，类别或文本截断时拒绝绘图，不能冒充完整结果。预览图明确标为近期预览。

每轮最多3张、每张最多20000行；折线显示约2000点，散点最多显示5000对，CSV保留完整快照数据。缺失不补零；重复时间的折线读数标未知；过多断点拒绝抽样。直方图包含全部有效值，最后一箱含最大值。不同指标使用独立面板，未知单位明确标注，不根据字段名猜测。

成功后返回结构化图表引用，聊天卡片提供缩放、图例、悬停、全屏、每页50行的数据视图和PNG/SVG/CSV下载。图片注明来源、时间和显示抽样；CSV包含快照数据，不是整库导出。历史消息保存引用，数据位于本机 `.dcma-runtime/charts/`；刷新及重启只恢复原快照，不自动查询新数据。重新查询以原绝对时段发送新消息，不覆盖旧图。清除浏览器记录或移除本机快照后可能无法恢复。

快照最大4MiB、本机最多100份，达到上限须人工归档，不自动删除。目录0700、文件0600，继承现有Git忽略规则。读取端点为 `GET /api/tools/charts/{uuid}.json` 和 `.csv`，不接受任意路径或写入。

绘图专项验证见 [绘图验收记录](绘图验收记录_2026-10-22.md)。浏览器的组织下载策略可能阻止CSV；本项目不会绕过该策略。
